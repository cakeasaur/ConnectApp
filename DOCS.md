## Зачем это приложение

ConnectApp решает одну задачу: **читать поток данных с платы и показывать его в реальном времени** — без ноутбука, без проводов к ПК, прямо с телефона.

Плата шлёт строки через UART (например `T1:27.3 T2:24.1 AX1:-480 AY1:4 AZ1:-989`), приложение парсит их, строит графики, считает FFT/RMS/Калман, пишет CSV, отправляет в Home Assistant через MQTT.

**Типовой сценарий использования:**
1. Прикрепил датчики к оборудованию
2. Подключился по BT/Wi-Fi/USB
3. Нажал `monitor` — данные пошли
4. Смотришь графики, анализируешь вибрацию, температуру
5. Записал сессию кнопкой REC → экспортировал CSV/PDF

## Архитектура и транспорты

```
Плата (UART) ──► BT SPP (HC-05/HC-06/ESP32)  ─┐
                Wi-Fi TCP (ESP32, любой сокет)   ├──► DataParser ──► SensorDataBus ──► UI / Graphs
                USB OTG (любой CH340/CP2102)     ┘
                                                  └──► MQTT Bridge ──► Home Assistant / Grafana
```

| Транспорт | Когда использовать |
|---|---|
| **Bluetooth SPP** | Classic BT (HC-05/HC-06, ESP32 SPP). Дальность ~10 м, без Wi-Fi инфраструктуры |
| **Wi-Fi TCP** | ESP32 в режиме сервера. Дальность до 100 м, через роутер — без ограничений |
| **USB Serial OTG** | Плата напрямую в телефон через OTG-кабель. Нет радио = нет помех |
| **MQTT мост** | Ретрансляция данных в облако/локальную сеть поверх любого из трёх выше |

## Главный экран

```
┌─────────────────────────────┐
│  ConnectApp                 │
│  Двусторонняя связь         │
│                             │
│  [● Bluetooth (SPP)]        │
│  [⊕ Wi-Fi (TCP)   ]        │
│  [⚡ USB serial    ]        │
│  [≈  MQTT мост    ]        │
│  [▶  Тест (mock)  ]        │
│  [📋 История записей]       │
└─────────────────────────────┘
```

| Элемент | Что делает |
|---|---|
| **Bluetooth** | Открывает экран BT-подключения. Сканирует классические BT-устройства (SPP), показывает сопряжённые и найденные |
| **Wi-Fi (TCP)** | Открывает экран Wi-Fi. Вводишь IP и порт платы, подключаешься как TCP-клиент |
| **USB serial** | Открывает экран USB. Список подключённых OTG-устройств (по VID:PID), выбираешь нужное |
| **MQTT мост** | Настройка MQTT-ретрансляции: публикует данные сенсоров, подписывается на команды |
| **Тест (mock)** | Запускает симулятор платы — синусоиды на температуре, шум на акселерометрах. Позволяет изучать интерфейс без реального железа |
| **История записей** | Список сохранённых сессий (raw-дамп потока). Просмотр, replay, экспорт |

**Баннер статуса** (появляется сверху при активном соединении):  
Показывает текущий транспорт и статус. Нажатие — быстрый переход на активный экран.

**Карточка "Последнее устройство"** (появляется если есть история):  
Один тап — переподключиться к последнему устройству без поиска.

## Экраны подключения

### Bluetooth (SPP)

```
[🔍 Поиск]  [⛔ Стоп]           ← сканирование
────────────────────────────────
Сопряжённые:
  HC-05  (AA:BB:CC:DD:EE:FF)   ← тап = подключить
  ESP32-BT
Найденные:
  Device_01
────────────────────────────────
[ Подключить ]  [ Отключить ]
[ Графики    ]  [ Отправить ]
[ ● REC ]       [ ■ STOP    ]
────────────────────────────────
Лог:
  → monitor
  ← T1:27.3 T2:24.1 ...
```

| Кнопка | Действие |
|---|---|
| **Поиск** | BT Discovery — 12-секундное сканирование эфира. Требует разрешения BLUETOOTH_SCAN (API 31+) |
| **Стоп** | Остановить сканирование досрочно |
| **Устройство (тап)** | Подключиться к выбранному устройству через RFCOMM/SPP |
| **Подключить / Отключить** | Явное управление соединением |
| **Графики** | Открыть экран графиков с текущими данными (активно только когда подключено) |
| **Отправить** | Отправить команду в поле ввода на плату |
| **● REC / ■ STOP** | Начать/остановить запись raw-потока в файл. После STOP — диалог шеринга |
| **Очистить лог** | Очистить буфер лога и сбросить данные сенсоров |

**Быстрые команды** (чипы над полем ввода):  
Предустановленные команды (`monitor`, `test`, `calib`, и пользовательские). Настраиваются в Настройках → Быстрые команды.

**HEX-режим** (переключатель в настройках):  
Поле ввода принимает байты через пробел: `AA 55 01 FF`. Полезно для бинарных протоколов.

**Статусбар соединения:**
- `Не подключено` → `Подключение…` → `Подключено` → `Переподключение (попытка N)` → `Соединение потеряно`

---

### Wi-Fi (TCP)

Аналогичен BT, но вместо поиска устройств — поля **IP-адрес** и **Порт**.

**Валидация:** порт должен быть 1–65535, IP — непустой. Кнопка **Подключить** активна только при корректных данных.

**История подключений** (dropdown под полем IP):  
Последние 5 адресов, тап — автозаполнение. Кнопка «Очистить историю» — удалить все.

**Авто-реконнект:** при потере соединения делает до 5 попыток с нарастающей задержкой (настраивается).

---

### USB Serial (OTG)

```
[🔄 Обновить]
────────────────────────────────
USB-устройства:
  CH340  (VID:1A86 PID:7523)   ← тап = подключить
  CP2102 (VID:10C4 PID:EA60)
────────────────────────────────
Скорость: [9600 ▾] [115200 ▾]
```

**Особенности:**
- Не требует сопряжения в отличие от BT
- Работает через USB Host API Android (OTG-кабель обязателен)
- Поддерживает CH340, CP2102, FTDI и другие стандартные мосты
- Идентификация по VID:PID — не по имени, поэтому список всегда точный

## Экран графиков

Главный рабочий экран. Открывается из любого экрана подключения кнопкой **Графики**.

### Тулбар и кнопки

```
← [⬚][✕] [📷] [🔔] [❄] [PDF] [CSV]
```

| Кнопка | Функция |
|---|---|
| **←** | Назад к экрану подключения |
| **⬚ (курсор)** | Переключить режим crosshair: одиночный / двойной (Δt, ΔY между двумя точками). Иконка активна = dual-режим |
| **✕** | Очистить курсоры (появляется только если курсор установлен) |
| **📷** | Скриншот экрана → системный шеринг (WhatsApp, Telegram, почта…) |
| **🔔** | Настройка threshold-алертов: порог на любой канал → вибрация + уведомление |
| **❄** | Заморозить / разморозить графики. При заморозке данные продолжают приходить, но экран стоит — можно читать значения спокойно |
| **⊞ (zoom reset)** | Сброс pinch-зума (появляется только когда zoom активен) |
| **PDF** | Генерировать PDF-отчёт со всеми графиками и статистикой → шеринг |
| **CSV** | Экспорт всех данных в CSV-файл (timestamp + T1/T2/AX1/AY1/AZ1/AX2/AY2/AZ2) |

**Кнопки под тулбаром:**

| Кнопка | Функция |
|---|---|
| **calib** | Отправить команду `2` на плату — запустить калибровку акселерометров |
| **test** | Отправить команду `3` — быстрый тест платы |
| **▶ monitor / ■ stop** | Отправить команду `1` — запустить/остановить поток данных с платы |

### Управление окном времени

```
окно:  [🔍-]  [  все  ]  [🔍+]  [∞]
```

| Элемент | Функция |
|---|---|
| **🔍−** | Увеличить временное окно (показать больше истории): ×1.5, макс 60 минут |
| **🔍+** | Уменьшить окно (приблизить последние секунды): ÷1.5, мин 5 секунд |
| **текст** | Текущее окно: "5с", "30с", "2мин", "все" |
| **∞** | Показать все накопленные данные (без фильтра по времени) |

**Pinch-zoom (жесты прямо на графике):**
- Два пальца → сдвинуть / растянуть → зумирует временну́ю ось
- Drag одним пальцем (когда зум активен) → прокрутка по истории
- Двойной тап → сброс зума
- Индикатор `×2.5` (bottom-right) → текущий коэффициент зума

### Оверлеи (наложения на графики)

```
overlays:  [envelope]  [±σ]  [⚠ alert]  [phase-lock]
```

| Оверлей | Что рисует | Когда полезен |
|---|---|---|
| **envelope** | Полупрозрачная лента min/max в скользящем окне | Видна «огибающая» амплитуды вибрации. Нарастающая огибающая = нарастающая поломка |
| **±σ** | Полоса ±1 стандартного отклонения вокруг среднего | Моментально видны выбросы за норму. Точки вне полосы = аномалия |
| **⚠ alert** | Пунктирная горизонтальная линия с меткой `⚠ overheat` / `⚠ vibration` | Визуальный порог — красная зона на графике. Дополнение к уведомлениям |
| **phase-lock** | Автоматически подбирает окно = 2 периода доминирующей частоты | Периодический сигнал «стабилизируется» — каждый кадр ровно 2 цикла. Для апериодических данных — fallback |

### Основные графики

#### Температура °C

```
T1: min 26.46 / avg 27.01 / max 27.55 °C
T2: min 23.45 / avg 24.01 / max 24.55 °C
┌──────────────────────────────────────┐
│ ● T1  ● T2              T1=26.73    │
│ 28.0  ~~~~~~~~~~~~~~~~~~~~          │ ← T1 (красный)
│ 27.0  ~~~~~~~~~~~~~~~~~~            │
│ 26.0                                │
│ 25.0          ~~~~~~~~~~~~~~~~~     │ ← T2 (голубой)
│ 24.0  ~~~~~~~~~~~~~~~~~             │
│ 0s    17s   34s   51s   68s   102s  │
└──────────────────────────────────────┘
```

**Что показывает:** температуру с двух каналов T1 и T2 в реальном времени.

**Для боевых задач:**
- Мониторинг **температуры ESC/мотора дрона** — перегрев заметен за секунды до выхода из строя
- Мониторинг **генератора** — тренд температуры говорит о нарастающей нагрузке
- **Тепловой баланс** — разница T1-T2 показывает направление теплового потока
- При включённом `alert` — телефон завибрирует при T > порога, даже если экран заблокирован

#### Акселерометр 1 и 2

```
ax=-480.00 · ay=4.00 · az=-989.00          ← header
┌──────────────────────────────────────────┐
│ ● ax  ● ay  ● az           ax1: -480 LSB│
│  580  ████████████████████████████  102 │
│  349        ax/ay (левая ось)       101 │ ← az правая ось
│  118                                100 │
│  -114 ~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~│ ← шум вибрации
│  -345                                99 │
│  -576 ████████████████████████████   95 │
└──────────────────────────────────────────┘
```

**Две независимые Y-оси:**
- **Левая** — ax, ay (горизонтальная вибрация, единицы LSB, ±несколько сотен)
- **Правая** — az (вертикаль + гравитация ≈ 1000 LSB в покое, ±несколько единиц при вибрации)

Без разделения осей az (~1000 LSB) давит ax/ay (~50 LSB) в плоскую линию — ничего не видно.

**Crosshair (тап на графике):**  
Вертикальная линия на всех трёх чартах синхронно. В bubble-overlay: значения в момент тапа.  
Двойной crosshair (dual mode): показывает Δt и Δ(значение) между двумя точками.

**Для боевых задач:**
- **Вибродиагностика двигателей/редукторов** — нарастающая амплитуда ax/ay = начало разрушения подшипника
- **Сейсмический датчик периметра** — датчик на грунте, порог по RMS → уведомление при вибрации от шагов/транспорта
- **Детектор выстрела** — резкий импульс на az, счётчик, профиль нагрева ствола
- **Ориентация/наклон платы** — az ≈ 1000 означает горизонтальное положение

### Математический анализ

Скролл вниз после основных графиков. Все расчёты пересчитываются при каждом новом отсчёте.

#### 📊 Спектр вибрации ax1 (FFT)

```
пик: 2.34 Гц · амплитуда 48.2 · окно 256 · fs=10 Гц    [dB]
┌──────────────────────────────────┐
│ ██                               │
│ ███  │                           │
│ ████ │                           │
│ ████████                         │
│ ████████████                     │
│ 0   2.5Гц  5.0Гц                 │
└──────────────────────────────────┘
```

**Что считает:** FFT 256 последних отсчётов с окном Ханна. Ось X — частота 0..Nyquist (5 Гц при 10 Hz дискретизации), Y — амплитуда.

**Переключатель [dB]:** логарифмическая шкала вместо линейной. В dB-режиме слабые гармоники (-40 dB) видны наравне с главным пиком.

**Оранжевые пунктиры:** маркеры гармоник 2f, 3f, 4f от пика. Если они совпадают со столбиками — классический признак дефекта подшипника или зубчатой передачи.

**Для боевых задач:**
- Основная частота вибрации мотора = RPM / 60
- Гармоники 2f/3f/4f выше нормы → механический дефект
- Широкополосный шум без чёткого пика → случайные удары, нестабильное крепление

#### 🌊 Спектрограмма ax1 (STFT-waterfall)

```
STFT окно 64 · hop 400мс · 0..5.0 Гц · пик 2.34 Гц · dB-scale -60..0
5.0Гц ┌────────────────────────────────────────┐
      │░░░░████████████░░░░████████████░░░░████│
      │░░░░████████████░░░░████████████░░░░████│
      │░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░│
0 Гц  └────────────────────────────────────────┘
         -80с               now
```

**Что показывает:** эволюцию спектра во времени (STFT). Ось X — время, ось Y — частота, цвет — амплитуда (Turbo palette: синий=тихо, красный=громко).

**Читается как:** горизонтальная яркая полоса = стабильная частота вибрации. Вспышка = кратковременный удар. Нарастающая яркость = усиление вибрации.

**Для боевых задач:**
- Спектрограмма показывает **историю вибрации**, а не только текущий момент
- Характер изменения частоты при разгоне/нагреве двигателя
- Сейсмические события — видна точная временна́я метка удара/взрыва

#### 📐 Дескрипторы вибрации (ISO 10816)

```
ax1:  RMS: 312.4  Peak: 580.0  Crest: 1.86  Kurt: 2.11
ax2:  RMS: 287.1  Peak: 543.0  Crest: 1.89  Kurt: 2.04
```

| Метрика | Что значит | Норма | Тревога |
|---|---|---|---|
| **RMS** | Среднеквадратичная амплитуда. Общий уровень вибрации | Зависит от оборудования | Нарастающий тренд |
| **Peak** | Максимальный выброс за окно 128 отсчётов | — | — |
| **Crest** | Peak / RMS. Импульсный характер вибрации | 1.4 – 3.0 | **> 4** = ударная нагрузка, дефект |
| **Kurt** | Куртосис — «хвостатость» распределения | ≈ 3 (Гаусс) | **> 4** = одиночные удары, сколы |

**Crest > 4 / Kurt > 4** подсвечиваются красным.

**Для боевых задач:**
- **Crest нарастает** → механизм начинает бить, появляются зазоры
- **Kurtosis** — лучший ранний индикатор дефекта подшипника (появляется раньше чем RMS)
- Стандарт ISO 10816 используется для диагностики промышленных машин

#### 🔵 Ориентация (наклон A1)

```
Pitch: +12.3°   Roll: -5.1°    |a| = 1003 LSB
┌──────────────────┐
│      ( )         │ ← пузырёк = текущий наклон
│   o              │
│  (центр = горизонт)
└──────────────────┘
```

**Что показывает:** pitch/roll в градусах из акселерометра A1. Пузырьковый уровень: пузырёк уходит в сторону наклона.

`|a| ≈ 1000 LSB` = плата в покое (1g). Отклонение > 50 = внешнее ускорение.

**Для боевых задач:**
- Выставить горизонт орудия / антенны / солнечной панели без дополнительного инструмента
- Контроль крена дрона/транспорта через MQTT
- `|a|` резко возрастает при ударе — детектор удара

#### 🌀 Orbit / Lissajous (фазовые портреты)

```
ax1 vs ay1:          ax2 vs ay2:
   ╭──────╮              ╭──╮
  ╱        ╲           ╱    ╲
 │  •        │         │      │
  ╲        ╱           ╲    ╱
   ╰──────╯              ╰──╯
```

**Что показывает:** траекторию вектора ускорения в плоскостях (ax vs ay, ax1 vs ax2). По форме фигуры Лиссажу можно определить характер вибрации:

| Форма | Характер вибрации |
|---|---|
| Окружность | Вращательное движение, равномерный дебаланс ротора |
| Эллипс | Вращение + асимметрия |
| Хаотичное облако | Случайная вибрация, широкополосный шум |
| Линия | Вибрация в одной плоскости (недостаточная жёсткость крепления) |

**Для боевых задач:** быстрый визуальный диагноз типа вибрации без математики.

---

#### 📡 Phosphor persistence (CRT-осциллограф)

```
▓▓░░░░░░░░░░░░░░░░░░▓▓
░▓▓▓░░░░░░░░░░░░░░▓▓▓░
░░▓▓▓▓░░░░░░░░░▓▓▓▓░░░
```

**Что показывает:** историческую яркость сигнала как у аналогового осциллографа. Часто посещаемые уровни — ярче, редкие — тусклее. «Следы» остаются.

**Для боевых задач:** наглядно показывает envelope сигнала и типичный диапазон без математики. Если сигнал нестационарный — по фосфору видна история.

---

#### 🔗 Cross-correlation ax1 ↔ ax2

```
best lag: +3 отсчёта (+0.30 с) · R=0.84
ax2 отстаёт от ax1 на 3 отсчёта
───────────────────────────────────────
          ╭─────╮
─────────╯       ╰─────────────────────  ← R(lag)
         ↑ пик
```

**Что считает:** нормализованную взаимную корреляцию двух акселерометров. `R=1.0` = сигналы идентичны. Лаг = задержка между ними.

**Для боевых задач:**
- Два датчика на одной конструкции: лаг = время распространения вибрации → оценить расстояние до источника
- Сейсмика: два датчика в разных точках грунта → грубая триангуляция источника вибрации (взрыв, машина, шаги)
- Лаг ≈ 0, R > 0.9 = оба датчика «чувствуют» одно и то же

---

#### 🌡️ Тепловой поток (закон Фурье)

```
ΔT = 3.20 °C · Δx = 50 мм · k = 401 Вт/(м·К) [медь]
∇T: +64.0 К/м     q: +25664 Вт/м²     →: T1→T2
```

**Что считает:** q = −k × (T2−T1)/Δx — тепловой поток по закону Фурье.  
Предположение: датчики разнесены на 50 мм вдоль медного стержня.

**Для боевых задач:** оценка интенсивности нагрева/охлаждения. Если q нарастает — тепловой поток в системе усиливается. Стрелка → показывает направление переноса тепла.

---

#### 🎯 Kalman fusion (слияние акселерометров)

```
ax1: -480.0   ax2: -471.0   x̂: -476.3   P: 0.012
```

**Что делает:** Kalman 1D фильтр сливает два независимых измерения (ax1 и ax2) в одну оптимальную оценку x̂.

- `Q=0.5` — шум процесса (динамика сигнала)
- `R1=5, R2=8` — дисперсии шума датчиков
- `P` — ковариация оценки (чем меньше, тем увереннее фильтр)

**Для боевых задач:** если один из датчиков начнёт давать выбросы/сбои, Kalman автоматически снизит его вес. Надёжная оценка ускорения при двух резервных датчиках.

---

#### 📈 Скорость и смещение (∫a·dt, ∫∫a·dt²)

```
A1 скорость (LSB·с):        A1 смещение (LSB·с²):
vx ~~~~     vy ──           dx ~~~~     dy ──
```

**Что делает:** численное интегрирование ускорения → скорость → смещение методом трапеций с drift-коррекцией (linear detrend).

**Единицы:** LSB·с и LSB·с² — относительные. Для перевода в мм/с нужна калибровка (sensitivity акселерометра в мг/LSB).

**Для боевых задач:**
- Оценка перемещения конструкции без GPS
- Характер движения: скорость близка к нулю в покое, нарастает при воздействии
- Drift-коррекция не даёт графику «убежать в бесконечность» из-за DC-смещения датчика

## MQTT мост

Ретранслирует данные сенсоров в MQTT-брокер (Home Assistant, Grafana, собственный сервер).

```
connectapp-a3f7d2e8/temp1    → {"value": 27.34, "ts": 1716000123456}
connectapp-a3f7d2e8/temp2    → {"value": 23.91}
connectapp-a3f7d2e8/accel1x  → {"value": -480.0}
...
connectapp-a3f7d2e8/status   → "online" / "offline" (will-message)
connectapp-a3f7d2e8/cmd      ← подписка (если включена)
```

| Настройка | Описание |
|---|---|
| **Включён** | Мастер-переключатель MQTT |
| **Хост / Порт** | Адрес брокера (например `192.168.1.10 / 1883`) |
| **TLS** | Шифрование соединения (MQTTS, порт 8883) |
| **Доверять любым сертификатам** | Для self-signed CA в локальной сети. ⚠ Не для публичных брокеров |
| **Логин / Пароль** | Авторизация на брокере. Пароль хранится в EncryptedSharedPreferences |
| **Client ID** | Уникальный ID клиента. Пустое = авто-генерация |
| **Префикс топиков** | Пространство имён (по умолчанию `connectapp-<8hex>` — уникальный для каждой установки) |
| **QoS** | 0 = fire-and-forget, 1 = at least once, 2 = exactly once |
| **Retained** | Брокер хранит последнее значение — новые подписчики получают его сразу |
| **Throttle (мс)** | Минимальный интервал между публикациями на канал. 0 = без ограничений |
| **Подписка на команды** | Слушать `{prefix}/cmd` → отправлять на плату. ⚠ Любой на брокере может управлять платой — включать только при ACL |

**Для боевых задач:**
- Данные со всех точек наблюдения на одном Grafana-дашборде
- Home Assistant automation: T1 > 80°C → алерт в Telegram
- MQTT через VPN = управление платой из любой точки мира

## Применение в боевых задачах

### Сценарий 1: Мониторинг БПЛА

```
Плата ESP32 на раме:
  T1 → термистор ESC,  T2 → термистор мотора
  A1  → вибрация рамы (3 оси)

Телефон оператора подключён по Wi-Fi 2.4/5 ГГц.

Что смотреть:
  - T_ESC > 80°C → снизить нагрузку / посадить немедленно
  - RMS вибрации нарастает → разбаланс/повреждение пропеллера
  - Kurtosis > 4 → удар, возможно посторонний предмет попал в ротор
  - FFT: новая гармоника → механический дефект
```

### Сценарий 2: Сейсмический датчик периметра

```
Плата + акселерометр закопаны/приклеены к забору/грунту.
Подключение по BT или Wi-Fi.

Настройки:
  - Threshold alert на AX1 > 200 LSB (RMS)
  - MQTT → Home Assistant → уведомление на все телефоны

Что анализировать:
  - Одиночный импульс (Kurtosis >> 3): одиночный удар, шаг рядом
  - Периодическая вибрация: движущийся транспорт (FFT покажет частоту)
  - Cross-correlation двух датчиков в разных точках → направление движения
```

### Сценарий 3: Мониторинг генератора / дизеля

```
T1 → выхлоп, T2 → корпус генератора
A1 → вибрация на корпусе

Норма: T2 < 60°C, RMS < 200 LSB, Crest < 3

Алерты:
  - T1 > 300°C → перегрев выхлопа
  - Crest > 4 → механический дефект (нарушение крепления)
  - FFT: гармоника оборотов пропала → неравномерная работа цилиндров
```

### Сценарий 4: Диагностика орудия / оружия

```
Датчик на стволе или затворной группе.

AZ1: импульс выстрела → счётчик выстрелов (по пикам выше порога)
T1:  нагрев ствола → профиль нагрева
RMS, Crest: механические характеристики отката

MQTT → ведение журнала выстрелов с timestamps
```

## Формат данных платы

Приложение ожидает строки (line-separated, `\n` или `\r\n`):

```
T1:27.34 T2:23.91 AX1:-480 AY1:4 AZ1:-989 AX2:-471 AY2:3 AZ2:-992
```

**Обязательных полей нет** — работают любые комбинации:

| Поле | Описание |
|---|---|
| `T1:<float>` | Температура 1 в °C |
| `T2:<float>` | Температура 2 в °C |
| `AX1:<int>` | Акселерометр 1, ось X (LSB) |
| `AY1:<int>` | Акселерометр 1, ось Y |
| `AZ1:<int>` | Акселерометр 1, ось Z |
| `AX2:<int>` | Акселерометр 2, ось X |
| `AY2:<int>` | Акселерометр 2, ось Y |
| `AZ2:<int>` | Акселерометр 2, ось Z |

**Регистр нечувствителен:** `t1:` и `T1:` одинаковы. Неизвестные поля игнорируются.

Минимальный пример (только температура):
```
T1:27.3 T2:24.1
```

Только акселерометр:
```
AX1:-480 AY1:4 AZ1:-989
```
