## 1. Безопасность 🔴
Из первого аудита, ещё не тронуто.
- **TLS-обход MQTT.** `MqttBridge.kt` использует `InsecureTrustManagerFactory` при `trustAllCerts` — принимает любой сертификат (MITM тривиален). Убрать совсем или заменить на pinned self-signed CA.
- **Cleartext MQTT по умолчанию** (`MqttConfig`: port 1883, `useTls=false`). Пароль брокера и команды идут открытым текстом. Форсировать TLS.
- **FileProvider scope.** `file_paths.xml`: `<cache-path path="."/>` открывает весь cache. Сузить до подпапки `exports/`.
- **MQTT `subscribeCommands`** ретранслирует сырой текст в `CommandBus` без авторизации. Хотя бы предупредить/ограничить.

## 2. Рефакторинг: дедуп трёх ViewModel 🔴
`BluetoothViewModel` / `UsbSerialViewModel` / `TestViewModel` содержат почти идентичные ~150 строк:
- `parseChunk` (нормализация, `drainRecords`, парс, публикация в `SensorDataBus`);
- классификация текстовых строк в `CommandLog`;
- watcher foreground-сервиса;
- фильтр `CommandBus`.

→ вынести в общий `SensorStreamProcessor` (или базовый VM / extension). **Самое назревшее** — правки приходится делать в трёх местах синхронно.

## 3. Баги внутри графиков (Compose) 🟡
Из аудита архитектуры. Чинить точечно, **графики не переписывать**.
- **`NeonChart`**: top-level мутабельные `Paint` (`haloPaint`/`corePaint`/`sigmaPaintCache`/`textPaintCache`) общие на все инстансы — гонка/ломает preview. → `remember { Paint() }`.
- **`SpectrogramView`**: `fillSpectrogramBitmap` как side-effect внутри `remember`. → `derivedStateOf` / `LaunchedEffect`.
- **`Accel3DChart`**: `flatMap{flatten()}` (~600 Float-объектов на кадр) в draw. → прямой проход `maxAbs` по xs/ys/zs.
- Дубль формулы padding `density*25f` трижды (`NeonChart`) → один хелпер.

## 4. Архитектура (по желанию, если приложение будет жить) 🟡
- **Бизнес-логика в Activity**: `buildCsv`/PDF в `GraphActivity` → в VM/UseCase (тестируемость, переживает пересоздание Activity).
- **`SettingsRepository`** создаётся по экземпляру в каждом VM и в `GraphScreen` → один общий.
- **Трио транспортов** (`*Client`+`*Repository`+`*ViewModel` ×3) за общим интерфейсом `Transport` — только если будет рост. Иначе не трогать.
- ❌ НЕ тащить DI-фреймворк ради ~5 синглтонов, не прятать шины за абстракции «на будущее».

## 5. Производительность / ресурсы 🟢
- `SensorDataBus.push`: `deque.toList()` (копия) на каждый отсчёт под lock — GC-давление при дампе/высокой частоте.
- `SessionRecorder.appendChunk`: `flush()` + `launch` на каждый чанк под global lock — теряется буферизация.
- `LogBuffer`: debounce без trailing-edge — последний чанк может не попасть в `text` до `flush()`.

## 6. Math / DSP мелочи 🟢
- FFT окно Ханна с делителем `N-1` vs `N` (рассинхрон с фиксированным coherent-gain ×2) — в пределах допуска, но неточно.
- Слабые FFT-тесты (`output length` подаёт нули, проверяет только размер).
- `DataParser` compact-`T` regex может ловить ложные температуры из текста.
- Кросс-корреляция: нормировка по полному окну при ненулевом lag не гарантирует диапазон [-1,1] из KDoc.

## 7. Протокол платы / фичи 🟡
По присланному преподом примеру (HyperTerminal): команды-слова, промпт `>`, `log dump` → `=== RRD Event Log ===`, связь 2400 8-N-1.
- **Кнопка «Log dump»**: ESC → пауза → `log dump`, результат в консоль.
- **(опц.) Разбор RRD Event Log** (`Idx|Date/Time|Event|S|Cur|Min|Max|Unit|Dur`) в нормальную таблицу/экран.
- **CRLF по умолчанию** как терминатор + чип `AT+HELP`/`help` для AT-консольных плат.
- **USB: 2400 бод** в настройках для этой платы.
- Решить размещение встроенной консоли/ESC: сейчас консоль на Графиках, ESC и «Лог команд» на Bluetooth — возможно, консоль нужна и на Bluetooth.
- Косметика: разделители таблицы `---+---` (без букв) фильтруются из `CommandLog` — при разборе логдампа учесть.
